Why you'd use it

Rules people build with Event Engine

Six examples from the template library. Each one runs entirely on the camera.

Night-time intruder response

When

Object Analytics spots a person inside the perimeter zone

Only if

It's between 19:00 and 06:00 and the system is armed

Then
  • Start recording
  • Sound the siren and strobe
  • Switch on the alarm output for 30 seconds
  • Send a Telegram message with a snapshot
  • Show a warning on the video

Catch tailgating at a door

When

The door opens and motion is detected within 8 seconds of each other

Only if

It's outside office hours

Then
  • Record 30 seconds
  • Send a Telegram alert with a snapshot
  • Pulse the alarm relay

Room air quality on a speaker display

When

Every 60 seconds

Then
  • Read CO₂, temperature and humidity from a nearby Axis air quality sensor
  • Show the values on an Axis speaker display

No broker, gateway or server: one Axis device reads another directly.

Follow the sun

When

The sun sets at the camera's location

Then
  • Switch the camera to night mode
  • Turn on the IR illuminator at 80%

A matching sunrise rule switches back. The times adjust through the year automatically.

Block-listed plate to a Milestone alarm

When

AXIS License Plate Verifier reads a plate

Only if

The plate is on the block list and hasn't been reported yet

Then
  • Raise an alarm in Milestone XProtect that shows the plate and a snapshot

The camera as a SCADA edge node

When

Every 30 seconds

Then
  • Read the latest sensor values
  • Publish them as Sparkplug B to Ignition or another SCADA host

Replaces the industrial gateway normally placed between the camera and the plant network.

How it works

One camera, any number of rules

Each rule listens for one or more triggers, checks its conditions and then runs its actions in order. Rules can also check and control other Axis devices on the network.

Features

Powerful when you need it, simple when you don't

🔗

Combine triggers

Run a rule when any trigger fires, when all fire within a few seconds, or only while all are active, like a door opening plus motion.

🛰️

Control other Axis devices

Detect on one camera, check a second device, then act on a third: speakers, sirens, I/O modules and paging consoles included.

🧠

Variables and counters

Arm and disarm the system, count events and escalate once a limit is reached.

✏️

Live values in messages

Drop the camera name, time, a sensor reading or the GPS speed into any alert, overlay or message.

🛑

Cooldowns and limits

Avoid alert floods with a minimum gap between runs and a cap per minute, hour or day.

Questions

Good to know

Do I need a server or cloud service?

No. Rules run entirely on the camera. External services are only contacted if you add an action that sends to them.

Does it replace the camera's built-in event rules?

It extends them. Event Engine uses the same device events, adds many more actions, and can fire its own events that the camera's built-in rules and a VMS can react to.

Can a rule affect the camera?

Yes. Actions can start recordings, move PTZ, change overlays, use I/O, or operate supported signals. Review and test rules before enabling them.

Where is the full manual?

See the online manual, the use cases and the README.

Is Event Engine an official Axis product?

No. It is an independent community-developed ACAP.
